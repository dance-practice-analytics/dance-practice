# Installable web app (PWA) and GitHub Pages

Covers FR-3.8.2 (installable on iOS and desktop) and FR-3.8.6 (offline viewing). The Android
app (FR-3.8.1) is a separate Capacitor build and does not use the service worker.

## Files

| File | Role |
| --- | --- |
| `public/manifest.webmanifest` | Name, colours, icons. `start_url` and `scope` are relative (`./`), so it works from any sub-path. |
| `public/icons/*.png`, `public/favicon.svg` | Generated by `node scripts/make-icons.mjs` (headless Chrome). Re-run it after changing the mark and commit the output. |
| `public/sw.js` | Hand-written service worker. |
| `public/register-sw.js` | Registers the worker and announces updates. Loaded from `index.html`. |
| `.github/workflows/deploy-pages.yml` | Builds with the Pages base and deploys on push to `main`. |

## Install

- Chrome / Edge (desktop, Android): install icon in the address bar, or menu → *Install app*.
- iOS Safari: Share → *Add to Home Screen*.

The worker is only registered on the deployed site (HTTPS, not `localhost`), never on the Vite
dev server and never inside the Capacitor shell, so `npm run dev` and `npm run e2e` are not
affected. To try it on a local production build:

```
npm run build
npx vite preview --port 4173
# in the browser console, then reload:
localStorage.setItem('dpa:sw', 'on')
```

Remove it again with `localStorage.removeItem('dpa:sw')` and DevTools → Application →
Service workers → Unregister.

## What works offline

| Works offline | Needs a connection |
| --- | --- |
| Opening the app (shell: HTML, JS, CSS, icons) after one online visit | Signing in, and refreshing an expired session |
| Pose estimation on local clips, once the model and WASM runtime have been used online one time (about 23 MB, cached on first use, not at install) | Loading or saving anything in Supabase (sessions, attempts, keypoints, metrics) |
| Whatever the app itself keeps on the device | AI practice notes (`generate-feedback`) |
| | Web fonts (Google Fonts); offline the system font is used |

The service worker caches files, not data. Reviewing an already-processed attempt offline
needs the app to keep that attempt's keypoints and metrics on the device (IndexedDB); the
worker never stores Supabase responses.

## Cache rules (`public/sw.js`)

- `dpa-shell-<VERSION>`: `index.html`, manifest, icons. Navigations are network-first (5 s
  timeout), falling back to the cached shell.
- `dpa-assets-<VERSION>`: hashed files in `assets/`. Precached on install by following the
  references from `index.html`, cache-first afterwards.
- `dpa-pose-<POSE_VERSION>`: `assets/vision_wasm_internal-*` and `mediapipe/*.task`.
  Cache-first, stored on first use. Range requests are answered from the cached copy.
- Never cached or intercepted: other origins (Supabase, Google Fonts), requests with an
  `Authorization` header, anything that is not a GET, video/audio, `clips/`. Study clips are
  local `blob:` URLs and never reach the worker.

## Updates and cache version

A new worker installs in the background and waits. It takes over when every tab/window of
the app is closed, or when the page asks for it:

```ts
window.addEventListener('dpa:update-ready', (e) => {
  // show a toast; on click:
  e.detail.apply() // activates the new version and reloads
})
// if the event fired before the listener was added: window.dpaUpdate?.apply()
```

Nothing reloads on its own, so an update cannot interrupt clip processing.

- **Every deploy** is a new version: the workflow appends the commit to `VERSION` in
  `dist/sw.js` (`v1` → `v1-abc1234`). Old shell and asset caches are deleted on activation;
  unchanged hashed files are copied over instead of downloaded again.
- **Bump `VERSION`** in `public/sw.js` by hand (`v1` → `v2`) when deploying somewhere without
  the workflow, or to force a clean shell.
- **Bump `POSE_VERSION`** only when `@mediapipe/tasks-vision` is upgraded or the `.task` file
  is replaced. It makes every device download the ~23 MB again.

## GitHub Pages

One-time setup in the repository (`dance-practice-analytics/dance-practice`):

1. Settings → Pages → Source: **GitHub Actions**.
2. Settings → Secrets and variables → Actions → **Variables**:
   - `VITE_SUPABASE_URL` (`https://<project-ref>.supabase.co`)
   - `VITE_SUPABASE_PUBLISHABLE_KEY` (`sb_publishable_...`)

   Both are public values (RLS protects the data), kept out of the source so the project can
   be changed without a commit. Secrets with the same names also work.
3. Supabase → Authentication → URL Configuration: add
   `https://dance-practice-analytics.github.io/dance-practice/` to the site/redirect URLs.
4. Commit `public/mediapipe/pose_landmarker_full.task` (9.4 MB), or let the workflow download
   it from Google's model storage when it is missing.

The workflow sets `BASE_PATH=/<repo name>/`; `vite.config.ts` uses it as `base` (default `/`).
To build the same thing locally:

```
# PowerShell
$env:BASE_PATH = '/dance-practice/'; npm run build
# Git Bash (stop it from rewriting the path)
MSYS2_ENV_CONV_EXCL=BASE_PATH BASE_PATH=/dance-practice/ npm run build
```
